# Bot memory: Family Book conventions

Generic facts for the bot's memory. User-specific values (storage type, role as owner or member, display name, root folder id and OneDrive path, year folder and workbook ids, receipts folder id, currency, holiday region) are added at setup and never stored in this repo.

- Language: do not ask which language to use, and do not save one. Chat, item notes and descriptions in the book, holiday descriptions, and digests follow the language the user is writing in. When a routine runs and nobody has just written, use the Grok Bot app or system language. These stay English on purpose: the workbook template's sheet names, category labels and notes, the receipt-list headers, receipt file names (`YYYY-MM-DD HHMM - Store - TOTAL.ext`), and this repo's skill, routine, and doc files. Translated templates (for example `template/family-book-template-fr.xlsx`) may be added later on request.
- Role: `owner` if this bot started the book, `member` if it joined a book someone else started. Only the owner's bot runs the new-year routine. A member's bot attaches to the new year's book in December and never creates one.
- Root folder: the owner keeps one folder named exactly `Family Book` at the top of Google Drive or OneDrive. Its id is in memory, and on OneDrive the path `Family Book` from the top of OneDrive is too. Each `Family Book - YYYY` folder, its workbook, its `receipts` folder, and `Family Book - Templates` live inside that root. The root id is not the year folder id. On the next run, if a year folder or the templates folder is still at the top of the owner's own drive, the owner says so in one line and moves it into the root. A move keeps ids and share links. A member has no root id, does not create the root, and does not move folders. A member keeps the shared year folder id.
- Display name: saved when they give one. Setup asks for it when they join, or when they say other people will log too. Item notes then include it, for example `Costco (Mom)`. If there is no name, use the merchant alone. If they tell you a name later, save it and use it from then on.
- Every photo or email receipt gets a saved file in the shared `receipts` folder for that year, named `YYYY-MM-DD HHMM - Store - TOTAL.ext` (time omitted when unknown). A photo or email receipt does not count as logged until its file is saved there.
- Email is optional and read-only: never send, reply to, forward, label, or delete email. Do not ask which inbox to scan. On every scan, use every Gmail account and every Outlook account that is ready. If none is ready, skip email. When they connect one later ("connect Outlook", "add my other Gmail"), scan that account too, including on the daily routine.
- Never log the same purchase twice. The rule is the top section of the family-book skill, and that phrase is part of the skill description. Before every write, check the hidden Log tab (the authoritative list) and the month Transactions and Receipts sections. A statement line is the same purchase when its key matches: last 4, post date, amount, normalized description, and occurrence number. Gather every candidate. Same receipt number at the same store is one purchase. With no number on one side, the same store, the same total to the cent, and a date within ±1 day is one purchase. Auto-attach only when there is exactly one candidate. Two or more candidates are one question that lists every one of them, and nothing is written until they answer. Different receipt numbers are different purchases. An open question is one Log row with Status `question` and no grid amount. Its dates go in Log column H, and a later identical receipt joins that row. A rule 2 auto-attach with two dates keeps the earlier transaction date, the same as a yes on rule 3. An email sent date does not. A fuel AUTH code is not a receipt number. A pending row with the same receipt key (the number at that store, or the short store name, the transaction date, and the total when the number is blank) is resumed through the write steps. It is not a rule 2 match candidate. A match attaches the extra file and does not add the amount. Files keep their own names. Source entries are joined with `, ` on Log column A and on the Receipts helper File list (column CB). A photo is `photo`. An email is `email gmail/<addr> <msgid>`. A second photo is `photo, photo`. A question row's Source is `open question: candidates <dates>; <source>`. A return (negative) is its own row. Do not keep a dedupe list in this bot's memory. Append the pending Log row with the target cell in Where written, then write the amount, then the file, then the section row, then the finished status. A retry reads that cell. If Where written is blank, search that day's category block, including each item cell of a split and Fixed Expenses or Income rows, for a cell that already holds this amount and whose text contains the short store name. Record it and write nothing. Only if none is found, use the first empty cell. A confirmed duplicate is marked `superseded` and kept. The SHA-256 in the Log is how a re-sent file is recognized, including after a rename. Read and write the daily block through column BS. Day 31 is BR and BS.
- Book version: Annual Summary `C46`. `v2.0` means this book is current. Anything older, including `v1.2.4`, still needs the family-book-migrate skill. The owner's bot runs it once for every older year book in the `Family Book` root. A member does not. The migration does not change number cells unless the user confirms a duplicate fix, and it does not apply a formula that changes a displayed total unless the user confirms that fix. A flagged duplicate is kept. Rows are not deleted. A month whose formula change does not change a displayed total is applied immediately. Only months whose displayed total would change wait for one yes.
- Statements live in `Family Book - {year}/statements/{Issuer Product}-{last4}/YYYY-MM-DD statement.ext`. The file and the Statements row use the statement date's year. Each transaction is written in the book for its post-date year. A statement has no transaction id. The key is last 4, post date, amount, normalized description, and occurrence number. Display text keeps `&` (T&T stays T&T). `&` becomes `and` only while matching.
- Cards are optional at setup. After the book exists, ask once which cards they have (issuer, product, last 4), or learn them from the first statement. Do not block setup on the answer. Do not ask for a bank account. With no bank file the book tracks expenses only. A big unknown charge is one whose absolute amount is at least `big_charge_threshold` (75 in the book's currency). Ask once, then remember the answer on the merchant map. Known brands such as Costco match with or without a city (`Costco` and `Costco Burlington` are one merchant on the map).
- Card payments and transfers are not expenses. A card payment pays down the oldest unpaid statement for that card when the payment posts on or after that statement's date. A partial payment reduces what is left and the reminder continues. A payment dated before the statement date does not count toward that statement. Due reminders read every unpaid row on the Statements sheet (full due date and amount still owed). They fire 3 days before that date and on that date. If the amount is unknown, the reminder says to check the statement. It never leaves the amount blank. Cards shows only the latest statement.
- On OneDrive, re-download the workbook right before every write and upload it immediately afterward, so another member's edits are not overwritten. Google Sheets is the better shared book, because several editors can write at the same time.
- Use the `family-book` skill for setup and logging. The template lives at https://raw.githubusercontent.com/Skybatan/family-book/main/template/family-book-template.xlsx.
- Use the short merchant name (for example `Costco`, `Amazon`, `Home Depot`). `Costco.ca` is `Costco`.
- If an amount or category is a guess, say so and ask.
