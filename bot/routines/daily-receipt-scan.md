# Routine: Daily receipt scan

- **Schedule:** daily, around 8:00 PM in the user's timezone.
- **Create when:** at least one Gmail or Outlook account is ready. If none is ready at setup, skip this routine and create it when they connect one later (family-book skill, section 0a). Both the owner and a member who joined the shared book get this routine.
- **Uses:** the `family-book` skill (the "Never log the same purchase twice" section, then sections 1c, 1d, 3, 3a, 3b, 3c, 4, and 6), the statement-reader, transaction-category, expense-category, and receipt-match skills, and, for the owner, the `family-book-migrate` skill when a book is older than v2.0. A statement-ready issuer email is handed to the statement-ready routine and is not logged as a purchase.

## Prompt

Run the family-book skill's email scan for the household Family Book this bot writes to. First download `https://raw.githubusercontent.com/Skybatan/family-book/main/bot/skills/family-book/SKILL.md`. If its body differs from the installed family-book skill, save the new body over it. Keep the name `family-book`. Set the description from the downloaded file, one quoted line that starts with `Never log the same purchase twice.` Do not fold it and do not drop that sentence. Also download `https://raw.githubusercontent.com/Skybatan/family-book/main/bot/skills/family-book-migrate/SKILL.md` and save it as the family-book-migrate skill. Download `statement-reader`, `transaction-category`, `expense-category`, and `receipt-match` from `https://raw.githubusercontent.com/Skybatan/family-book/main/bot/skills/<name>/SKILL.md` when they are not installed. If GitHub can't be reached, continue with the installed skill. If this bot joined the book, do not create a `Family Book` root, do not move any folder, and do not run the migration. Keep the year folder id, workbook id, and receipts folder id already in memory. If Annual Summary `C46` is not `v2.0`, say once that the owner's bot will update the book, and do not insert a Transactions or Receipts section. If the Log sheet is missing, add it (section 3b). Try to hide it. If you cannot, ask once and keep going.

If this bot started the book (role `owner`, or no role saved and the year folder is in this user's own My Drive or OneDrive), follow section 1c once before logging. That section tells them in one line only when a top-level `Family Book - YYYY` or `Family Book - Templates` folder still has no `Family Book` parent, then moves it into the root. Then follow section 1d. For every year workbook in the `Family Book` root whose Annual Summary `C46` is missing or is not `v2.0`, run the family-book-migrate skill before logging. That skill says one line before it starts. A book older than v1.2.4 finishes the v1.2.4 checkpoint (receipt list, file names `YYYY-MM-DD HHMM - Store - TOTAL.ext`, the freeze unmerge, the content hash) and then copies those rows into the Receipts section. A book that is already `v1.2.4` skips the checkpoint and only gains the v2.0 sections. That copy still converts Source ` | ` to `, ` and rewrites an old `open question` Source. It does not change number cells. It is safe to resume. It reports existing duplicates and waits for a yes before correcting an amount. It never deletes a row. A formula fix that would change a displayed total waits for one yes for the whole book, listing every month and the before and after amount. When `C46` is already `v2.0`, skip the migration. If `D46` contains `Pending duplicates:` or `Pending formula fixes:`, mention that in one line only inside a digest you are already sending. Do not apply the fix.

Then check which Gmail and Outlook accounts are ready now (GetMcpServerStatus or GetDynamicTools status: ready, needsAuth, needsGrant, or missing). Scan every account that is ready, including one connected after setup. If a new account is ready, scan it too and say so in one line. If none is ready, send nothing and do not ask them to connect email. Search those accounts for new order confirmations, receipts, and invoices since the last scan (Amazon, Costco, Home Depot, Walmart, and any other merchants). On the very first run for an inbox, cover the last 30 days and mention, in the language of this chat (or the Grok Bot app or system language if nobody has just written), that older receipts from this year can be backfilled on request. Before any write, apply the skill's "Never log the same purchase twice" rules, across photos, every ready inbox, and the other family bots. Gather every candidate. Do not stop at the first hit. Same receipt number at the same store is one purchase, including an order confirmation and its later receipt email, and a store slip and its eReceipt. With no number on one side, the same store, the same total to the cent, and a date within ±1 day is one purchase. Auto-attach only when there is exactly one candidate. Two or more candidates, such as an Oct 10 receipt with an Oct 11 rule 2 match and an Oct 3 rule 3 candidate, are one question in the digest that lists every candidate. Do not attach to Oct 11. A later identical receipt joins that same question, and its date is appended in Log column H. A single rule 3 candidate is one yes/no. Do not write an amount until they answer. Do not guess. A match attaches the new file (Receipts column AA links to the primary file and reads `photo +1` when there is another) and appends the new source on Log column A and on the Receipts helper File list (column CB), joined with `, `. A photo is `photo`. An email is `email gmail/<addr> <msgid>`. A second photo is `photo, photo`. A question row's Source is `open question: candidates <dates>; <source>`. On a match, files keep their own names. A pending row with the same receipt key is resumed, not treated as a rule 2 match. A bare yes asks which of the dates already listed, for example "Which date does it match: Oct 11 or Oct 3? Reply no if it's new." A return is its own row. A fuel AUTH code is not a receipt number. The same file is recognized by the SHA-256 in Log column O, including after a rename. Skip marketing. Skip a shipping notice that has no order number and no total. An issuer email that says the statement is ready is not a receipt. Hand it to the statement-ready routine. Do not log it as a purchase.

Log each new purchase into the current year's Family Book (Google Sheet or Excel workbook; ids are in memory) on the right month sheet, day, and category, splitting multi-category receipts as the skill describes. Day 31 is columns BR and BS. Read and write the daily block through column BS. All bots share that one book and its one receipts folder.

Every email receipt MUST also be saved as a file in that year's receipts folder (ids in memory), following the skill's section 3a: the PDF attachment if there is one, otherwise the email rendered as a PDF or a one-page PNG, named `YYYY-MM-DD HHMM - Store - TOTAL.ext` (omit the time when it is unknown; `Costco.ca` is `Costco`). Check the file shows the merchant, date, and total before uploading. Follow section 3's write order: append the pending Log row with the target cell in Where written, write the amount, then the file (section 3 step 9), then the Receipts or Transactions row, then the finished status (`awaiting statement`, `cash`, `no receipt`, or `matched`). A retry reads the recorded cell. If Where written is blank, search that day's category block, including each item cell of a split and Fixed Expenses or Income rows, for a cell that already holds this amount and whose item text contains the short store name, such as `Costco (Mom) milk`. Record it and write nothing. Only if none is found, use the first empty cell. A name collision is `YYYY-MM-DD HHMM - Store - TOTAL - 2.ext`. Do not delete a Log row. A confirmed duplicate is marked `superseded`. A photo or email receipt is not finished until that file is saved. A pasted text receipt uses the File label `text`. A receipt with no card is status `cash`. Item text includes the display name when one is in memory, for example "Costco (Mom)". The Receipts Store column does not. Also check that rows already in the Log tab have a file in the receipts folder, and save any that are missing. Do not keep a separate dedupe list in this bot's memory. The template and these repo files come from GitHub, not from the owner's Google Drive. Reading this family's own receipt files is required. On OneDrive, re-download the workbook right before every write and upload it immediately afterward. This is read-only for email: never reply, forward, send, label, or delete anything.

If this bot joined the book (member) and next year's book is not in memory yet, look for it in December, or when a receipt is dated next year. The folder is the one the owner shared, named "Family Book - YYYY". You may see it only as a shared folder. Save its year folder id, workbook id, and receipts folder id. Do not create that book, do not create a `Family Book` root, and do not move any folder. If you newly link it, say so in one line. If it is not there yet, wait for the owner's bot.

Report to the user in this Grok Bot chat, in the language they write in here, or the Grok Bot app or system language when nobody has just written. Send a short digest of what was logged (merchant, date, total, category, saved file, and who logged it), what was attached to a purchase already in the book, any near-match question, and anything unclear that needs their call. Item notes written into the book are in that same language. Receipt file names stay `YYYY-MM-DD HHMM - Store - TOTAL.ext`. If nothing new was found, you did not just link next year's book, and you did not just migrate, send nothing.
