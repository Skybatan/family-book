# Routine: Daily receipt scan

- **Schedule:** daily, around 8:00 PM in the user's timezone.
- **Create when:** at least one Gmail or Outlook account is ready. If none is ready at setup, skip this routine and create it when they connect one later (family-book skill, section 0a). Both the owner and a member who joined the shared book get this routine.
- **Uses:** the `family-book` skill (the "Never log the same purchase twice" section, then sections 1c, 1d, 3, 3a, 3b, 3c, and 4) and, for the owner, the `family-book-migrate` skill when a book is older than v1.2.4.

## Prompt

Run the family-book skill's email scan for the household Family Book this bot writes to. First download `https://raw.githubusercontent.com/Skybatan/family-book/main/bot/skills/family-book/SKILL.md`. If its body differs from the installed family-book skill, save the new body over it. Keep the name `family-book`. Set the description from the downloaded file, one quoted line that starts with `Never log the same purchase twice.` Do not fold it and do not drop that sentence. Also download `https://raw.githubusercontent.com/Skybatan/family-book/main/bot/skills/family-book-migrate/SKILL.md` and save it as the family-book-migrate skill. If GitHub can't be reached, continue with the installed skill. If this bot joined the book, do not create a `Family Book` root, do not move any folder, and do not run the migration. Keep the year folder id, workbook id, and receipts folder id already in memory. If Annual Summary `C46` is not `v1.2.4`, say once that the owner's bot will update the book, and do not insert a receipt list. If the Log sheet is missing, add it (section 3b). Try to hide it. If you cannot, ask once and keep going.

If this bot started the book (role `owner`, or no role saved and the year folder is in this user's own My Drive or OneDrive), follow section 1c once before logging. That section tells them in one line only when a top-level `Family Book - YYYY` or `Family Book - Templates` folder still has no `Family Book` parent, then moves it into the root. Then follow section 1d. For every year workbook in the `Family Book` root whose Annual Summary `C46` is missing or is not `v1.2.4`, run the family-book-migrate skill before logging. That skill says one line before it starts. A book older than v1.2.3 gets a receipt list rebuilt from the Log, the saved files, and the original emails, and files renamed to `YYYY-MM-DD HHMM - Store - TOTAL.ext`. A v1.2.3 book keeps its list and gets the v1.2.4 patch. It does not change number cells. It is safe to resume. It reports existing duplicates and waits for a yes before correcting an amount. A formula fix that would change a displayed total also waits for a yes. When `C46` is already `v1.2.4`, skip the migration. If `D46` contains `Pending duplicates:` or `Pending formula fixes:`, mention that in one line only inside a digest you are already sending. Do not apply the fix.

Then check which Gmail and Outlook accounts are ready now (GetMcpServerStatus or GetDynamicTools status: ready, needsAuth, needsGrant, or missing). Scan every account that is ready, including one connected after setup. If a new account is ready, scan it too and say so in one line. If none is ready, send nothing and do not ask them to connect email. Search those accounts for new order confirmations, receipts, and invoices since the last scan (Amazon, Costco, Home Depot, Walmart, and any other merchants). On the very first run for an inbox, cover the last 30 days and mention, in the language of this chat (or the Grok Bot app or system language if nobody has just written), that older receipts from this year can be backfilled on request. Before any write, apply the skill's "Never log the same purchase twice" rules, across photos, every ready inbox, and the other family bots. Check the Log key first. Same receipt number at the same store is one purchase, including an order confirmation and its later receipt email, and a store slip and its eReceipt. With no number on one side, the same store, the same total to the cent, and a date within ±1 day is one purchase. The same clear store with the same total within 7 days is a near match: one yes/no question in the digest. Do not guess, and do not log it until they answer. A match attaches the new file (the File cell links to the primary file and reads `photo +1` when there is another) and does not add the amount. A return is its own row. A fuel AUTH code is not a receipt number. Skip marketing. Skip a shipping notice that has no order number and no total.

Log each new purchase into the current year's Family Book (Google Sheet or Excel workbook; ids are in memory) on the right month sheet, day, and category, splitting multi-category receipts as the skill describes. Day 31 is columns BR and BS. Read and write the daily block through column BS. All bots share that one book and its one receipts folder.

Every email receipt MUST also be saved as a file in that year's receipts folder (ids in memory), following the skill's section 3a: the PDF attachment if there is one, otherwise the email rendered as a PDF or a one-page PNG, named `YYYY-MM-DD HHMM - Store - TOTAL.ext` (omit the time when it is unknown; `Costco.ca` is `Costco`). Check the file shows the merchant, date, and total before uploading. Follow section 3's write order: Log row first as pending with the receipt key, then the amount, then the file, then the month-list row, then `done`. A retry checks the Log key first and does not write the amount again. A receipt is `done` only once that file is saved. Item text includes the display name when one is in memory, for example "Costco (Mom)". The list's Store column does not. Also check that rows already in the Log tab have a file in the receipts folder, and save any that are missing. Do not keep a separate dedupe list in this bot's memory. The template and these repo files come from GitHub, not from the owner's Google Drive. Reading this family's own receipt files is required. On OneDrive, re-download the workbook right before every write and upload it immediately afterward. This is read-only for email: never reply, forward, send, label, or delete anything.

If this bot joined the book (member) and next year's book is not in memory yet, look for it in December, or when a receipt is dated next year. The folder is the one the owner shared, named "Family Book - YYYY". You may see it only as a shared folder. Save its year folder id, workbook id, and receipts folder id. Do not create that book, do not create a `Family Book` root, and do not move any folder. If you newly link it, say so in one line. If it is not there yet, wait for the owner's bot.

Report to the user in this Grok Bot chat, in the language they write in here, or the Grok Bot app or system language when nobody has just written. Send a short digest of what was logged (merchant, date, total, category, saved file, and who logged it), what was attached to a purchase already in the book, any near-match question, and anything unclear that needs their call. Item notes written into the book are in that same language. Receipt file names stay `YYYY-MM-DD HHMM - Store - TOTAL.ext`. If nothing new was found, you did not just link next year's book, and you did not just migrate, send nothing.
